# Архитектура Chatwoot

Этот документ описывает техническую архитектуру проекта Chatwoot, включая бэкенд, фронтенд, инфраструктуру и ключевые процессы.

## 1. Обзор Системы

Chatwoot — это платформа для взаимодействия с клиентами (Customer Engagement Suite) с открытым исходным кодом. Она построена по принципу **монолитной архитектуры** (Modular Monolith) с использованием Ruby on Rails для бэкенда и Vue.js для фронтенда. Приложение спроектировано как API-first, где фронтенд взаимодействует с бэкендом исключительно через REST API и WebSocket.

## 2. Технологический Стек

### Бэкенд
-   **Язык**: Ruby 3.4.4
-   **Фреймворк**: Ruby on Rails (~7.1)
-   **API**: REST API (JSON), WebSocket (ActionCable)
-   **Аутентификация**: Devise, Devise Token Auth, OmniAuth
-   **Авторизация**: Pundit
-   **Фоновые задачи**: Sidekiq 7 (на базе Redis)
-   **Событийная модель**: Wisper (Pub/Sub внутри процесса)
-   **Поиск**: Searchkick / Opensearch / PgSearch
-   **AI/ML**: `ruby-openai`, `pgvector` (векторный поиск), `ai-agents`

### Фронтенд
-   **Фреймворк**: Vue.js 3
-   **Сборщик**: Vite
-   **CSS**: Tailwind CSS v3
-   **State Management**: Pinia / Vuex
-   **Routing**: Vue Router
-   **Charting**: Chart.js

### База Данных и Хранение
-   **Основная БД**: PostgreSQL 16
    -   Использует расширение `pgvector` для AI-функций (Embedding).
-   **Кэш и Очереди**: Redis
-   **Файловое хранилище**: ActiveStorage (поддержка AWS S3, Azure Blob, GCS, Disk)

## 3. Архитектура Бэкенда (Rails)

Бэкенд следует паттернам MVC, но значительно расширен дополнительными слоями для инкапсуляции бизнес-логики:

### Структура Директорий (`app/`)
*   **`models/`**: Модели данных (ActiveRecord). Основные сущности:
    *   `Account`: Корневая сущность мультитенантности.
    *   `Inbox`: Канал связи (Email, Twitter, WhatsApp и др.).
    *   `Conversation`: Группирует сообщения.
    *   `Message`: Единица переписки.
    *   `Contact`: Конечный пользователь.
    *   `User`: Оператор/Администратор.
*   **`controllers/`**: Обработчики HTTP запросов.
    *   `api/v1/`: Основной API для десктопной и мобильной версии.
    *   `api/v1/widget/`: API для виджета чата на сайтах клиентов.
    *   `api/v1/platform/`: API для управления платформой (супер-админы).
    *   `public/api/v1/`: Публичный API (например, для порталов самообслуживания).
*   **`services/`**: Сервисные объекты (Service Objects). Вся сложная бизнес-логика вынесена сюда. Примеры:
    *   `Message::CreateService`: Создание сообщения.
    *   `Notification::PushService`: Отправка пуш-уведомлений.
*   **`builders/`**: Для построения сложных объектов данных (например, JSON-ответов или контактов из VCard).
*   **`dispatchers/`**: Обработка событий и отправка вебхуков.
*   **`listeners/`**: Слушатели внутренних событий (через Wisper). Например, отправка email при создании нового тикета.
*   **`mailboxes/`**: Обработка входящей почты через ActionMailbox.
*   **`policies/`**: Правила доступа (Pundit).
*   **`workers/`** (или `jobs/`): Фоновые задачи (отправка писем, выполнение правил автоматизации).

### Ключевые Процессы

1.  **Обработка Сообщений**:
    *   Входящее сообщение (через API или Webhook провайдера) -> Контроллер/Вебхук -> `Conversation` (поиск или создание) -> `Message::CreateService`.
    *   Сервис создает сообщение, запускает `AutomationRules`, отправляет данные через ActionCable (Realtime) и dispatchers (Webhooks).

2.  **Realtime (ActionCable)**:
    *   Клиенты (Dashboard, Widget) подписываются на каналы WebSocket.
    *   При изменениях данных (новое сообщение, смена статуса) сервер пушит обновления в соответствующие каналы.

## 4. Архитектура Фронтенда

Фронтенд разделен на несколько независимых приложений, живущих в монорепозитории (`app/javascript`):

1.  **Dashboard (`app/javascript/dashboard`)**:
    *   Основное приложение для агентов и админов.
    *   SPA на Vue 3.
    *   Использует `vue-router` для навигации.
    *   Взаимодействует с `api/v1`.
2.  **Widget (`app/javascript/widget`)**:
    *   Встраиваемый виджет чата для сайтов.
    *   Легковесное приложение, оптимизированное по размеру.
    *   Взаимодействует с `api/v1/widget`.
3.  **Portal (`app/javascript/portal`)**:
    *   Портал самообслуживания (Help Center).
    *   Публичная часть для чтения статей.
4.  **SDK (`app/javascript/sdk`)**:
    *   JS библиотека для интеграции виджета на сайты клиентов (`window.chatwootSDK`).

### Сборка
Используется **Vite** (`vite_rails`) для быстрой сборки и HMR (Hot Module Replacement) во время разработки.

## 5. Интеграции и Каналы

Chatwoot имеет модульную систему каналов (`Inbox`). Каждый тип канала имеет свои спецификации:

*   **API Channel**: Универсальный канал для кастомных интеграций.
*   **Email**: Использует IMAP/SMTP или API провайдеров (SendGrid, Mailgun) + ActionMailbox для парсинга входящих.
*   **Social & Messaging**:
    *   Facebook, Instagram, WhatsApp (через Cloud API или 360dialog), Telegram, Viber, Line.
    *   Реализованы через вебхуки: Провайдер шлет JSON на `/webhooks/...`, Chatwoot обрабатывает его и создает `Message`.

## 6. AI и Автоматизация

*   **Automation Rules**: Система правил "Если -> То" (например, "Если сообщение содержит 'цена', присвоить метку 'Sales'").
*   **Macros**: Заготовленные действия, выполняемые вручную агентом.
*   **AI функции**:
    *   Используется OpenAI API.
    *   Векторная база данных (pgvector) используется для семантического поиска похожих статей или ответов (Agent Assist).

## 7. Инфраструктура (Docker)

Проект полностью контейнеризирован (`docker-compose.yaml`):
*   `rails`: Основной веб-сервер (Puma).
*   `sidekiq`: Воркер для фоновых задач.
*   `postgres`: БД.
*   `redis`: Key-Value хранилище.
*   `vite`: Dev-сервер ассетов (в разработке).

## 8. Безопасность

*   **Аутентификация**: Devise Token Auth (access-token, client, uid в заголовках).
*   **Ролевая модель**: Super Admin, Account Admin, Agent.
*   **Валидация данных**: JSON Schema валидация для API.
